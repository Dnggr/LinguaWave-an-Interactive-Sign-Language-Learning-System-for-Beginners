## 5. Open questions before going further

1. **Content:** who writes/reviews real scenario titles + intro pitches for the other 64 categories, and on what timeline?
2. **Decision:** has anyone actually opened `datav2-compare.html`, played through Greetings both ways, and looked at the numbers? Phase 3's schema work got done ahead of this per an explicit request — the decision itself is still open.
3. **Real wiring:** if/when the decision is "yes, expand" — the next real work is wiring `ui.hintAvailableOn`/`ui.showHeartsOn`/`difficultyRamp`/`collapseMasteredMissions` into the actual `js/lesson.js`/`js/quiz.js`/`js/learn.js`, which is a bigger and riskier change than anything done so far (those files have been deliberately untouched this whole project).
4. **Analytics:** is a real backend event pipeline worth building at all, or does this stay a solo/small-team project where local observation is good enough?
5. **10 missions vs. 65 categories:** the implementation guide's V2 section specifies one continuous path of exactly 10 numbered missions. dataV2's schema (and now `v2-learn.html`) has 65 — one per live category, unrenumbered. Someone needs to decide whether the 65 map onto the 10 (several categories per numbered mission), whether the path is genuinely all 65, or whether "10" was aspirational/illustrative in the guide. Building Mission Overview / Lesson / Mastery Quiz screens without this answer risks building the wrong shape twice — `v2-mission-overview.html` numbers missions 1–65 for now, same open risk.
6. **Mission-detail screens:** Mission Overview (§6) is now built (`v2-mission-overview.html`) — number/title, goal, "You'll practice" chips, an estimated-effort figure, the mastery requirement, and a live Mastery Hearts display. **Update — no longer accurate, correcting for anyone reading top-to-bottom:** the guide's Lesson Architecture (§7–8) and a dedicated Mastery Quiz screen (§9) DO now exist as real V2 pages (`v2-lesson.html`/`v2-lesson.js` and `v2-mastery-quiz.html`/`v2-mastery-quiz.js` — see the Files table above and the two RESOLVED items below); "Start Mission"/"Start Mastery Quiz" only fall back to `pages/lesson.html`/`pages/quiz.html` for chapters outside the Chapters 1–2 sample (see item 7 below).
   **Update (Progress page session):** the guide's §13 Progress Dashboard is now also built as `v2-progress.html` — overall % (item-level, across every live mission), Signs Learned / Missions Completed / Signs to Review / Day Streak / Mastery Hearts stat tiles, a "Progress by Chapter" breakdown (dataV2's 12 `getCategoryGroups()` chapters, not v1's basic/medium/intermediate levels — chapters with zero live missions are left out rather than shown as a fake 0%), and a "Needs Review" panel. Unlike `pages/progress.html`, this one uses a REAL due rule (`getItemCompletedAt()` is at least 2 days old) instead of a "most recently practiced" fallback, because dataV2 actually has per-item timestamps (Phase 2) that the v1 app's own progress store doesn't. Still hands off to `pages/lesson.html` for the actual review — no dedicated V2 review flow exists yet (guide §12, still not started, see §3 above).
7. **Heart consumption timing — RESOLVED for the V2-native quiz (this revision, Task 2):** `js/v2-mastery-quiz.js` (Chapters 1–2 sample) now spends a heart per WRONG graded answer via a new, additive `consumeHeartForIncorrectAnswer()` in `js/data-v2.js`, not once on submit. `pages/quiz.js` was deliberately left completely untouched this revision (an earlier draft had wired a hook into it directly; that was reverted on request in favor of using the real V2-native quiz instead) — every other chapter still falls back to V1's `pages/quiz.js` via the original `consumeHeartForMastery()` on attempt *start*, unchanged.
8. **Mission ordering within a chapter — RESOLVED (this revision, Task 1):** missions used to lock/unlock strictly by flat position across all 65 (mission *N+1* opened only once mission *N* was done). That's replaced with chapter-level gating: a chapter unlocks once every mission in the previous chapter is 100% complete, and every mission inside an unlocked chapter is open at once — the learner picks the order within that chapter. See the new Session Log row below.
9. **Mastery Quiz completing the mission, not just its own QUIZ item — RESOLVED:** a pass on the V2-native Mastery Quiz (`v2-mastery-quiz.js`) used to call `markItemComplete()` for only the mission's own QUIZ item, which meant `getMissionProgress()` (done/total across EVERY item) rarely reached 100% after a "pass" — undermining the Mastery Quiz's whole point as an advanced-user skip path ("shouldn't need to complete every lesson after passing it"). Replaced with a new, additive `markMissionComplete(mission)` in `js/data-v2.js` that marks every item in the mission (reusing `markItemComplete()` per item, no parallel completion path), called from `finishQuiz()` on a pass. Verified with a Node harness against the real `alphabet` mission (0 → 1 progress, `'done'` status, chapter-unlock cascade confirmed for a full Chapter-1 pass). Full detail in `AI_MEMORY.md`.
10. **Review nav for a completed mission — RESOLVED, then reworked per follow-up:** `v2-lesson.js`/`v2-lesson.html` gained a review-nav bar, shown only once a mission is 100% complete (`getMissionProgress(mission) >= 1`), that lets a learner browse back through an already-mastered mission's items without writing to progress (routes through `renderItem()`, never `completeAndAdvance()`, so `markItemComplete()` is never called on a new item — and is a safe idempotent no-op even if the learner does click a stage's own answer/Continue button while reviewing). Initially built as Go-to-Start/Go-to-End; per explicit follow-up, reworked to `‹`/`›` step buttons that move one item at a time and self-disable at the mission's first/last item, updated on every render so they always track whatever item is currently on screen. `v2-mission-overview.js` also relabels a `'done'` mission's entry button "🔁 Review Mission" instead of "▶ Start Mission" (label-only, same URL). Full detail in `AI_MEMORY.md`.
